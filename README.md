# pstack-claude

Claude Code port of [cursor/plugins pstack](https://github.com/cursor/plugins/tree/main/pstack), generated by `convert.mjs`.
Nothing under `plugin/` is hand-edited.

## Update

```bash
node convert.mjs
```

Pulls upstream, regenerates `plugin/` from scratch, prints a GitHub compare link for what changed upstream, lists residual Cursor references, and runs `claude plugin update pstack@pstack-claude`.
Claude Code runs a cached copy under `~/.claude/plugins/cache/`, not this directory, so restart after a convert to load it.
The version is `<upstream version>+<upstream sha>.<content hash>`, so a `convert.mjs` or overlay change with upstream unchanged still counts as an update.

Residual count above 0 means upstream added a Cursor-ism the table does not cover.
Add a row to `REPLACEMENTS` in `convert.mjs` and re-run.

## Layout

- `convert.mjs` - the whole port: replacement table, adapter note appended to each skill, residual report.
- `overlays/` - files copied over the generated output. Only `setup-pstack`, whose model-budget logic is specific to Cursor model slugs.
- `plugin/` - generated Claude Code plugin.
- `.upstream/` - sparse clone of upstream, gitignored.

## Install (done once)

```bash
claude plugin marketplace add ~/Desktop/Projects/pstack-claude
claude plugin install pstack@pstack-claude
```

## Use

Entry point is `/pstack:poteto-mode`.
It also auto-triggers: a `UserPromptSubmit` hook (`plugin/hooks/hooks.json`) reminds Claude each turn to invoke it for coding tasks and skip it for general questions.
Tune the wording via `REMINDER` in `convert.mjs`. Say "no poteto" in a prompt to opt out for a task.
Direct: `/pstack:how`, `/pstack:why`, `/pstack:architect`, `/pstack:arena`, `/pstack:interrogate`, `/pstack:unslop`.
`/pstack:setup-pstack` sets the model per role in `~/.claude/rules/pstack-models.md`.

## Not ported

- `make-bot-ui` and `automations/benny` depend on Cursor Automations webhooks.
- Cross-vendor model panels. Claude Code subagents run Claude only, so panels are `fable, opus, sonnet`.
- Cloud worker environment. Workers run locally in worktrees.
