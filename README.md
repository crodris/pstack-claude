# pstack-claude

[![Verify](https://github.com/crodris/pstack-claude/actions/workflows/verify.yml/badge.svg)](https://github.com/crodris/pstack-claude/actions/workflows/verify.yml)

Claude Code port of [cursor/plugins pstack](https://github.com/cursor/plugins/tree/main/pstack), generated by `convert.mjs`.
Nothing under `plugin/` is hand-edited.

## Update

```bash
node convert.mjs
```

Pulls upstream, regenerates `plugin/` from scratch, prints a GitHub compare link for what changed upstream, lists residual Cursor references, and runs `claude plugin update pstack@pstack-claude`.
Claude Code runs a cached copy under `~/.claude/plugins/cache/`, not this directory, so restart after a convert to load it.
The version is `<upstream version>+<upstream sha>.<content hash>`, so a `convert.mjs` or overlay change with upstream unchanged still counts as an update.

Residual count above 0 means upstream added a Cursor-ism the table does not cover.
Add a row to `REPLACEMENTS` in `convert.mjs` and re-run.
The run exits 1 when residuals remain or when a skill in `MODEL_INVOKED` still carries `disable-model-invocation`.

## Checks

CI (`.github/workflows/verify.yml`) runs these on every pull request and push to main.
Run the same locally before committing:

```bash
node convert.mjs --check                 # plugin/ matches convert.mjs output
claude plugin validate --strict .        # marketplace manifest
claude plugin validate --strict plugin   # plugin manifest
bin/scan-skills.sh                       # SkillSpector, fails on any finding not in the baseline
```

`--check` regenerates into a temp dir at the upstream commit recorded in `plugin/.claude-plugin/plugin.json`, so it tests `convert.mjs` and `overlays/` without pulling new upstream changes.
It fails when `plugin/` differs, so commit the regenerated `plugin/` with any change to either.
It also moves `.upstream/` to that commit, and the next plain `node convert.mjs` resets it.

`bin/scan-skills.sh` scans every skill in `plugin/skills` with [NVIDIA SkillSpector](https://github.com/NVIDIA/SkillSpector).
The findings in `.skillspector-baseline.yaml` are upstream pstack text that was reviewed and accepted, so a failure after `node convert.mjs` means upstream added something new.
Read it, then add a rule with a reason or leave the update out.
When SkillSpector is missing, `bin/scan-skills.sh` prints the command that installs the version CI pins.

## Layout

- `convert.mjs` - the whole port: replacement table, adapter note appended to each skill, per-skill notes (`SKILL_NOTES`), residual report, `--check` mode.
- `bin/scan-skills.sh` and `.skillspector-baseline.yaml` - SkillSpector scan of the generated skills and its reviewed findings.
- `overlays/` - files copied over the generated output. Only `setup-pstack`, whose model-budget logic is specific to Cursor model slugs.
- `plugin/` - generated Claude Code plugin.
- `.upstream/` - sparse clone of upstream, gitignored.

## Install (done once)

```bash
claude plugin marketplace add ~/Desktop/Projects/pstack-claude
claude plugin install pstack@pstack-claude
```

## Use

Entry point is `/pstack:poteto-mode`.
It also auto-triggers: a `UserPromptSubmit` hook (`plugin/hooks/hooks.json`) reminds Claude each turn to invoke it for coding tasks and skip it for general questions.
Tune the wording via `REMINDER` in `convert.mjs`. Say "no poteto" in a prompt to opt out for a task.
Direct: `/pstack:how`, `/pstack:why`, `/pstack:architect`, `/pstack:arena`, `/pstack:interrogate`, `/pstack:unslop`.
`/pstack:setup-pstack` sets the model per role in `~/.claude/rules/pstack-models.md`.

## Not ported

- `make-bot-ui` and `automations/benny` depend on Cursor Automations webhooks.
- Cross-vendor model panels. Claude Code subagents run Claude only, so the generated panel defaults are `fable, sonnet`, and the `unlimited` budget in `setup-pstack` uses `fable, opus, sonnet`.
- Cloud worker environment. Workers run locally in worktrees.
